# Matching Service Integration Status

## Completed

- Added a backward-compatible `CaptionCue` model and retained cue start/end/text data in `CaptionDocument`.
- Batch preparation now creates approximately 320-500 character windows with one cue of overlap instead of submitting the full leading transcript as one item.
- Each batch item carries `source_video_id`, channel, upload date, caption language/source, segment order, YouTube start/end time, and original cue text.
- The matching client writes these fields into the CSV consumed by the central service.
- `partial_failed` is now treated as a terminal task status by the client poller.
- Regression tests: `python -m pytest -q` -> `10 passed`.
