# 匹配 API 接入能力评估

## 结论

当前两个项目已经具备接入条件，不需要把小说库、短剧字幕库、SQLite 或 Qdrant 复制到 YouTube 字幕核验助手。YouTube 项目作为客户端，通过登录态调用小说相似度服务；采集和转写留在桌面端，召回、最终判定和证据索引留在服务端。

当前接入链路已经覆盖：采集视频、获取字幕、无字幕时 ASR 兜底、按字幕 cue 生成约 320 至 500 字符的重叠片段、上传批量任务、轮询任务状态、按视频聚合结果。服务端现在返回 `matched`、`review_required`、`not_matched` 三种最终状态，客户端不能再以“返回候选”作为命中依据。

## 已具备的接口

- `POST /api/v1/auth/login`：登录并通过 HttpOnly Cookie 保持会话。
- `GET /api/v1/auth/me`：确认当前会话。
- `POST /api/v1/drama-subtitles/compare`：单条同步检测，返回 Top10 内部候选和最终 `decision`。
- `POST /api/v1/drama-subtitles/tasks`：上传 CSV 批量任务。
- `GET /api/v1/drama-subtitles/tasks/{task_id}`：读取任务进度和条目结果。
- `GET /api/v1/drama-subtitles/evidence-context/{window_uid}`：按需读取更长的中台字幕证据。

## 当前仍需注意

YouTube 助手只提交前几分钟字幕，这是当前业务设计，不是接口限制。长字幕必须继续按 cue 分段，否则长文本的词级召回会偏向开头。视频级结果是客户端聚合结果，单个片段的最终判定仍以服务端 `decision` 为准。

语义服务异常时，服务端会明确返回降级原因；客户端应显示“语义服务降级，未确认命中”，不能把语义近邻或普通候选转换成命中。`book_id` 当前是匹配库中的稳定书籍/剧集标识，若法务侧还需要另一套业务剧 ID，需要后续增加映射字段。

## 接入验收标准

单条检测应能读取 `decision.status` 和 `decision.reason`；批量聚合必须分别统计三种状态；每个视频保留视频 ID、频道、字幕语言、字幕来源、字幕片段序号以及 YouTube 起止时间；服务端任务状态为 `partial_failed` 时客户端必须停止轮询并展示部分失败；网络错误、401 会话过期和服务端 5xx 需要明确提示。

## 判断

现在可以进入真实 API 联调和小批量验收，不建议直接把客户端接入大规模生产任务。先使用 5 至 10 个视频验证登录、片段溯源、三态判定、待复核展示和导出，再扩大批量规模。
